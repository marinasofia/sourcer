# Security Policy

## Supported versions and reporting

Fixes target the current `main` branch and the latest 0.2.x release as
appropriate. Older releases do not have a separate maintenance commitment.
Do not put credentials, personal data, or exploit details in an issue.

Use **Security > Report a vulnerability** if GitHub offers that private channel.
Otherwise email the maintainer using the email address on the [portfolio contact page](https://marinasofia.github.io/#s06) with subject
`sourcer security`. Include the affected commit, impact, and a synthetic
reproduction, without active credentials or operator data. The maintainer
will review the report and coordinate mitigation and disclosure privately.

## Operating boundaries

- Keep API credentials in environment variables or a deployment secret store.
  `.env` is ignored; ignored files are not an access-control mechanism.
- This code repository is public and must hold no operator data. Skills vectors,
  profiles, resumes, answer banks, full posting results, and private logs belong
  only in the private data repository.
- Telegram starts in dry run and requires exact chat and user allowlists before
  it can send messages or accept commands.
- Every fetch of an outside URL goes through `sourcer.net`: public HTTPS only,
  each redirect checked, the connection pinned to the address that was checked
  (so a DNS answer that changes cannot reach a private address), and replies
  capped at 64 MB and 60 seconds. The opt-in browser fallback runs Chromium with
  its sandbox on, sends every page request through the same guard, allows GET
  only, and gets no secrets from the environment.
- Treat posting text and model output as untrusted. Schema checks, truncation,
  and parameterized SQL address specific risks; they do not establish overall safety.
- Model budget settings are estimates, not provider billing limits. Validate
  the chosen entry point and use provider-side controls where available.
- HTTP and MCP surfaces are intended for trusted operators. Restrict network
  access and add deployment authentication and resource controls as appropriate
  before exposing a scoring service.
- Review the IAM policy generated by `deploy/aws.sh` against the intended state
  bucket. Test recovery and concurrency behavior before depending on cloud state.
- No application form submission is implemented. Shortlist and feedback actions
  only change local database state.

See [maintainer guidance](docs/maintenance.md) for validation and branch rules.

## Security review before publishing

The project was penetration tested in October 2026, before this repository
was made public, across three areas: the network services, everything fetched
from the internet, and the path from a public pull request into the operator's
private side. Fixed as a result:

- unguarded fetches that could reach private addresses (SSRF), including
  through redirects, DNS rebinding, IPv6 forms that wrap IPv4, and a host
  smuggled into an Oracle URL;
- two regular expressions that a crafted careers page could make run for
  hours, and a compressed reply that expanded to 1 GB;
- a cost cap that applied per request instead of per process, a scoring
  service reachable without a token on loopback, and unbounded connections;
- secrets passed to the Claude CLI subprocess, and prompts visible in the
  process list;
- unhashed build tools, tag-pinned hooks and base images, and a cloud job that
  both browsed outside pages and held write access.

The code fixes each have a regression test.

## Free security checks

This repository uses Bandit for Python and zizmor for GitHub Actions
on every pull request, pushes to main, and a weekly schedule. They fail the job
on Python findings or workflow findings of low severity and above. Synthetic
scanner tests verify that unsafe Python and workflow expressions are rejected.
Scanner dependencies are hash locked in `security/requirements.txt` and updated
by Dependabot, separately from application dependencies.

These checks run in the GitHub runner. zizmor runs offline, and neither scanner
uploads code or results to a separate service or requires a Code Security license.
GitHub Actions usage remains subject to the account's existing allowance.
Ruff's security rules, dependency audits, and the operator-data hygiene check
remain in CI. Gitleaks remains available through the existing pre-commit hook.

This replaces the CodeQL integration that was unavailable while the
repository was private. Bandit checks Python syntax patterns, not CodeQL's deeper data-flow
analysis. zizmor checks workflow security, with online-only audits disabled.
Passing these checks does not establish that the application is vulnerability-free.
Narrow Bandit suppressions document reviewed fixed commands, bound SQL values,
constant predicates, and Lambda-isolated temporary paths. No rule is disabled
globally. See [local verification](docs/maintenance.md#security-scanner-verification).

## Network isolation limits

URL checks are defense in depth. DNS may change between validation and connection,
so these checks are not a substitute for an OS or container egress policy.
Run browser collection in an isolated environment without host credentials or
private-network access. Existing fixed-provider collectors have their own HTTP
helpers; the restricted session currently covers discovery, probes, and Telegram.
Telegram never follows POST redirects, and request errors suppress token-bearing URLs.
